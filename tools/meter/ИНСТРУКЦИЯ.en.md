# Direct UNI-T UT61D+ readings without image capture

[Русский, original TXT](ИНСТРУКЦИЯ.txt) | English

Tested with a real WCH CH9329 adapter, VID:PID `1A86:E429`. The vendor's UT61D+ application remained open during the check. Dependencies: Windows and Python 3; no additional packages or drivers are needed. CP2110 support is implemented from the specification but was not tested on this computer.

Commands from the project root:

```powershell
.\tools\meter\meter.ps1 --list
.\tools\meter\meter.ps1 --count 1
.\tools\meter\meter.ps1 --count 5 --interval 1
.\tools\meter\meter.ps1 --count 0 --interval 1 --latest output/meter/latest.json --log output/meter/readings.jsonl
```

The last command runs until Ctrl+C. It installs no background services, startup entries or scheduled tasks. By default, it takes one reading. `read_meter.py` can also be called directly with any installed Python 3.

Output is JSON: `display`, `mode`, `unit`, `volts`, `amps`, `quantity`, `flags`, `timestamp_utc`, `received_unix`, `checksum_valid`, `calibration_usable`, `frame_hex`. Each reading is requested from the instrument. Packet length, header and checksum are checked. The timestamp is when the computer receives the response, not when the ADC converts it. The UT61D+ model was identified by the user and `options.xml`; the tool does not request the model name from the meter, to avoid interrupting existing polling.

With HOLD/REL/MIN/MAX/PEAK, low battery, overload or an unsuitable mode, `calibration_usable=false`. For DC voltage and DC current, it may be true: the consumer must check `quantity`. `volts` is populated only in voltage modes; `amps` only in current modes, converting A/mA/uA to amperes. Units for other modes are not guessed. Coil calibration requires `quantity=current` and DCA/DCmA/DCuA; voltage calibration requires `quantity=voltage` and DCV/DCmV.

Reading `latest.json` alone does **not** prove that the instrument is currently connected: the last reading remains after the utility stops. Before calibration, request a fresh reading and check `ok=true`, `calibration_usable=true`, `checksum_valid=true` and the age of `received_unix` (no more than 3 seconds is recommended). If an attempt fails, `latest.json` is replaced with an error message.

If polling by two applications interferes, stop polling in the vendor utility. This reader does not terminate other processes or change the meter's mode, range, HOLD, REL, EEPROM settings or USB identifiers. The only multimeter command is measurement request `0x5E`.

## Findings about the vendor application

`DMM.exe` is a 32-bit Qt 5 application. Settings reside in `options.xml`. `CustomDmm.dll` implements the multimeter protocol and command queues. `CP2110.dll` and `SLABHIDtoUART.dll` provide the alternative Silicon Labs transport. `CH9329DLL.dll` contains `CH9329ReadData`/`CH9329WriteData` and uses Windows HID. The actual adapter found on this PC was CH9329, not CP2110. A CP2110 DLL in a directory does not prove that a CP2110 adapter is connected.

CH9329 uses a 65-byte Windows HID report:

```text
[00] [UART length] [UART data] [padding to 65 bytes]
```

UART measurement request:

```text
AB CD 03 5E 01 D9
```

UART measurement response:

```text
AB CD 10 [14 data bytes] [checksum, most significant byte first]
```

The checksum is the sum of all UART-frame bytes except the last two, modulo 65536. HID padding after the declared length may contain arbitrary bytes and must be ignored.

Captured real response (6.25 V DC):

```text
AB CD 10 02 31 20 20 20 36 2E 32 35 00 03 30 30 30 03 79
```

PE import/string analysis and testing the protocol on the device were sufficient. IDA, COM interception and modification of vendor files were unnecessary. `inspect_vendor.py` does not run the inspected DLLs' code.
