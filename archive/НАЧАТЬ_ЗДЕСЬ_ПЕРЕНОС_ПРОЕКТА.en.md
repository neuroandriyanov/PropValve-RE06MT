## 1. Purpose and status at the time

Sergey developed an ADAU1701 proportional-valve control board to replace the original Parker board. SigmaStudio processes DC control signals, not audio.

Intended operating logic:

```text
X4, 0..10 V input -> 0..3 A current command -> solenoid.
Measured actual current 0..3 A -> X3, 0..10 V monitor output.
```

A hardware analog loop built around TL494 regulates current. The DSP generates the command, filters/normalizes measurements and generates the monitor output. A separate digital PI/PID controller was not added.

Voltage-output, current-command, current-measurement and voltage-input calibrations were completed. The user then connected them into the working path. The final schematic and netlist were checked: the main connections matched the intended logic. At the time of this report, a full sweep of the combined system after those reconnections had not yet been run. Do not confuse individual calibration checks with a loaded test of the final system. **This historical pending-test statement was later superseded by the author's 31 October report.**

## 3. Hardware and board changes

DSP: ADAU1701. Software used: Analog Devices SigmaStudio 4.7. Project sample rate: 96 kHz. The project IC is `IC 1`; EEPROM is `IC 2`. For the test coil, the user had authorized calibration up to 3 A. Current sensor: ACS712, +/-5 A variant, nominal 185 mV/A. Main original PDF: `схема_плата/схема.pdf`.

Changes confirmed by the user:

- R43: 180 Ω → 10 kΩ, ADC1 current-measurement input.
- R42: 180 Ω → 10 kΩ, ADC0 voltage-command input.

The historical report suggested that the PDF might retain 180 Ω even though the physical board was changed; **the later review established that the supplied PDF already shows 10 kΩ**. R7/R12 are 51 kΩ in the schematic; no replacement was reported. They affect TL494 feedback, not just DSP measurement.

Channel mapping:

- ADC0: X4, external 0..10 V input through DA8.1/DA8.2 and R42.
- ADC1: current-sensor signal through DA4.1 and R43.
- DAC0 and DAC1: differential current command through DA5 and DA4.2.
- DAC2: reference leg of the 0..10 V output amplifier; its digital command = 0.
- DAC3: calibrated DA7.1 output-amplifier signal at X3.

DA8's input stage also uses refdac. At 0 V on X4, raw ADC0 is therefore around -0.0205 rather than -1; at 10 V it is around +0.7495. Real measurements after replacing R42 confirmed this.

**X3–X4 jumper:** the user connected output X3 to input X4 for input calibration. At the time of this report, removal after the final reconnection had **not** been confirmed. In the working circuit, X3 now represents actual current and X4 sets current. Leaving the jumper closes positive feedback through the entire control path. Check and remove it before applying an external command or testing the combined system. Check signal and common connections against the PDF.

The assistant had loaded projects into DSP RAM, not written EEPROM. After power removal, the old EEPROM program might load. Recheck the board state instead of assuming it matches the file.

## 4. Actual working SigmaStudio circuit

Command path:

```text
Input1, ADC0
  -> VIN_LPF_20Hz
  -> VIN_TABLE_0_10V
  -> VIN_LIMIT_MIN (> comparison with VIN_ZERO=0)
  -> VIN_LIMIT_MAX (< comparison with VIN_ONE=1)
  -> CURRENT_0_3A
  -> ZERO_OFF
  -> DAC0 and through Inv1 -> DAC1.
```

`VIN_MEAS_0_1` displays normalized input voltage after the limiters. Normalized value * 10 = X4 voltage in volts. `ADC0_RAW` is raw ADC0; `VIN_FILTERED` is after the LPF and before normalization.

`ZERO_OFF` is an AB in CD out conditional block:

```text
A = normalized command 0..1;
B = ZERO_CONSTANT = 0;
C = CURRENT_0_3A output;
D = ZERO_CONSTANT = 0;
condition A > B, otherwise output D.
```

`Inv1` must be enabled (coefficient -1). DAC0 is thus the positive table command and DAC1 its negative copy. At zero command, both digital commands are 0.

Actual-current and output-monitor path:

```text
Input1, ADC1
  -> CURRENT_LPF_20Hz
  -> FB_LIMIT_MIN (>, FB_MIN_CONST=-0.78)
  -> FB_LIMIT_MAX (<, FB_MAX_CONST=+0.70)
  -> I_FEEDBACK_0_1
  -> Interpolator1
  -> DAC3 -> DA7.1 -> X3.
```

`I_MEAS_0_1` displays normalized actual current. Normalized value * 3 = current in amperes. `ADC1_RAW` is the raw diagnostic signal before the LPF. `DC2_3 -> DAC2` must remain 0.

Transfer functions in engineering units:

```text
I_command = 3 * U_X4 / 10 A;
U_X3 = 10 * I_actual / 3 V, within the normalized scale.
```

For example, 5 V input commands 1.5 A. If actual current is 1.4 A, the monitor output should be about 4.67 V, not necessarily 5 V.

Last netlist: `проект_сигма/IC 1_Design1_parker_v0/net_list.cir2`. Its algorithm names differ from visible block names; map them through nid/pins and project data. Last report: 153 instructions, 38 Data RAM words, 45 Parameter RAM words. The project's sample rate was 96 kHz.

## 5. Calibration tables checked against the file

All values below are digital DSP data, not voltages directly at a pin. Control data generally use 5.23. DSP Readback returns 5.19: these are different formats and must not be decoded with the same divisor. Knots in each table are **evenly spaced** from Min to Max.

### A. 0..10 V input to normalized value, VIN_TABLE_0_10V

Min=-1; Max=+1; 5 ADC0 knots: -1, -0.5, 0, +0.5, +1.

```text
-1.2791438818551657
-0.6261845198303900
 0.02677484219438531
 0.6762541060654503
 1.3251072419904226
```

Negative and greater-than-1 coefficients at outer knots are intentional: they extend the calibration function across the full ADC range. `VIN_LIMIT_MIN/MAX` limit the final result to 0..1.

### B. Normalized command to current-control code, CURRENT_0_3A

Min=0; Max=1; knots: 0, 0.25, 0.5, 0.75, 1.

```text
0.0232187500000000
0.15965067486956522
0.29005681969979985
0.4185374112827678
0.5469142775502329
```

The first point is nonzero because of analog-controller offset. A separate `ZERO_OFF` provides complete shutdown.

### C. ADC1 to normalized actual current, I_FEEDBACK_0_1

Min=-0.78; Max=+0.70; knots: -0.78, -0.41, -0.04, +0.33, +0.70.

```text
0
0.2457725268587229
0.4934890604665372
0.7422585129761888
1
```

`FB_MIN_CONST` and `FB_MAX_CONST` must match this table's Min/Max.

### D. Normalized signal to 0..10 V output, Interpolator1

Min=0; Max=1; knots: 0, 0.25, 0.5, 0.75, 1.

```text
-0.001020
-0.077378
-0.153747
-0.230275
-0.306728
```

Negative values are correct: the DAC/output-stage polarity is such that a negative digital command increases X3 voltage. Calibration is valid with DAC2=0.

Separate files in `проект_сигма/`:

- `linintdacout.txt`, `linintdacout_calibrated.txt`: output coefficients.
- `current_command_0_3A.txt`: current command.
- `current_feedback_0_3A.txt`: current measurement.
- `voltage_input_0_10V.txt`: voltage input.
- `current_calibration_settings.json`, `voltage_input_settings.json`: ranges and settings.

A coefficient text file does **not** contain Min/Max, filter or limiters. Prefer the complete `.dspproj` for restoration.

## 6. Actual checks and accuracy limitations

The 0..10 V output was checked separately at several points; the observed difference from the multimeter reading was about 1 mV. Record: `output/meter/output_calibration_verification.json`.

Last separate current-command/measurement verification:

```text
command 0.5 -> multimeter 1.4995 A, DSP 0.4994895;
command 0.75 -> 2.251 A, DSP 0.7506799;
command 1 -> 2.998 A, DSP 0.9999981;
return to command 0 -> multimeter 0.000 A, DSP 0.
```

The largest command-versus-measured-current difference in the series was 7.5 mA; the largest DSP-versus-multimeter difference was about 2.8 mA. Record: `output/meter/feedback_final_verification.json`.

During warm-up/between series, the current-channel zero level drifted noticeably, in one series by the equivalent of approximately 26 mA. Cooling may produce small positive indicated values with actual zero current. A static table and LPF do not remove this drift. Automatic zeroing was not implemented. Do not claim guaranteed 2.8 mA accuracy at every temperature. Normalized-signal limiters do not protect against physical overcurrent. A signal already limited to one does not reveal the magnitude of an overrange condition; diagnostics require the raw measurement channel.

After R42 replacement, the 0..10 V input was checked against the voltmeter at 11 points:

```text
0 V -> approximately 0.00001;
4.999 V -> 0.4998142;
10.00 V -> 0.9998871.
```

The maximum observed difference was 1.326 mV referred to the input. Records:

```text
output/meter/voltage_input_raw.json
output/meter/voltage_input_filtered.json
output/meter/voltage_input_verify.json
```

This is a difference from the displayed meter reading in this series, not evidence of absolute metrological accuracy better than the multimeter itself.

**Linear-interpolator pitfall:** do not assume it correctly limits inputs outside Min/Max. Overrange inputs caused false readings at the scale edges. `FB_LIMIT_MIN/MAX` therefore precede the current table. For the voltage input, the full -1..1 table range is retained and the normalized output is limited separately. Do not remove the limiters or change ranges without rechecking the edges.

Before replacing R43=180 Ω, the current channel saturated at both ends; those initial measurements do not describe the current R43=10 kΩ calibration. `feedback_verification_without_limits.json` and other intermediate records describe diagnostic/unsuccessful stages. Use final/verify for final results, while remembering that those tests preceded the last working reconnections.

## 8. Starting on another PC

1. Copy the whole folder; open this file and the schematic PDF.
2. Install SigmaStudio 4.7 and the native driver for the actual USBi/programmer. Direct multimeter polling needs ordinary Python 3 for Windows (preferably 64-bit 3.11+). Captures through `capture_sigma.py` need Pillow.
3. Open the main file without changing `Design1_parker_v0.dspproj`. Renaming changes the compilation-output directory; old Python scripts with fixed `trap.dat` paths need adaptation.
4. Check actual connections, zero external command, R42/R43 values, absence of the calibration jumper and whether it is appropriate to energize the load.
5. Check the constants and `Inv1` above. The final working version already uses the external input; old manual test DC sources are absent.
6. When ready, load RAM using native Action → Link Compile Download (F7). Do not separately write EEPROM without a task to make the load persistent.
7. Readbacks: Ctrl+F11 enables continuous reading; Ctrl+F12 disables it. Check the >/< conditional blocks and coefficients before running a sweep.
8. First check the zero state and fresh multimeter readings, then check the operating range in stages. Do not treat old `latest.json` as live data.

## 9. Multimeter and direct polling without screenshots

The user identified the instrument as UNI-T UT61D+. Actual adapter used: WCH CH9329, HID VID:PID `1A86:E429`. This is not CP2110, although the vendor application includes CP2110 DLLs. The vendor utility could remain open; stop its polling if the requests conflict. IDA and Advanced Serial Port Monitor were not needed for the working solution.

Run from the PropValve root with an ordinary installed Python:

```text
py -3 tools/meter/read_meter.py --list
py -3 tools/meter/read_meter.py --count 1
py -3 tools/meter/read_meter.py --count 3 --interval 0.5
py -3 tools/meter/read_meter.py --count 0 --interval 1 --latest output/meter/latest.json --log output/meter/readings.jsonl
```

The last command runs until Ctrl+C and creates neither services nor startup entries.

For voltage, select DC V, use V/COM and connect in parallel with X3/X4. For current, use the appropriate current input/mode and connect in series with the coil. Check JSON `ok`, `checksum_valid`, `calibration_usable`, `quantity`, `unit`, `volts`/`amps` and freshness of `received_unix`. `calibration_usable=true` can apply to both current and voltage; always check `quantity`. HOLD/REL/MIN/MAX/PEAK/overload/low battery exclude a calibration reading. The instrument was left in DC V after the previous work; check it again in a new location.

## 10. SigmaStudio automation and nonportable parts

The main automation path was the native installed SigmaStudio API:

```text
tools/sigma/SigmaBridge.cs -> tools/sigma/SigmaBridge2.exe
tools/sigma/sigma_api.py
```

The earlier `SigmaBridge.exe` is not equivalent to the later `SigmaBridge2.exe`. .NET Framework and libraries from installed SigmaStudio are required. The historical `SigmaBridge.cs` used `C:\Program Files\Analog Devices\SigmaStudio 4.7`. If installed elsewhere, update the path and rebuild rather than copying arbitrary DLLs. The current package instead offers the configurable build described in SETUP.

Historical build example from PowerShell at the project root:

```powershell
& 'C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe' /nologo /r:System.Web.Extensions.dll /r:System.Drawing.dll /out:tools\sigma\SigmaBridge2.exe tools\sigma\SigmaBridge.cs
```

Example for listing API methods only:

```text
.\tools\sigma\SigmaBridge2.exe inspect
```

`call` accepts a method name and a JSON file containing an argument array. It is a full control API: some methods write parameters and load the DSP. Do not run an arbitrary saved `args.json` without inspecting it.

The API supports INSERT_OBJECT_POINT, CONNECT_OBJECT, DISCONNECT_OBJECT, GET/SET_OBJECT_PROPERTY, COMPILE_PROJECT, PARAMETER/REGISTER_READ and SAFELOAD. Some supplied method names have the typo SAFELAOD: use the names actually returned, not guessed corrections. Spaces in object names matter, such as original `ABCD 1`, not `ABCD1`. Branching needs a T Connection; reconnecting an occupied ordinary output through CONNECT_OBJECT can return false.

Observations on that PC:

- API SAVE_PROJECT failed with a regional-format error; ordinary Ctrl+S in the UI worked. Numeric fields require a decimal point; newly created blocks could receive commas and prevent saving.
- The UI rounded interpolator Min/Max to two digits. Check actual saved values instead of trusting entered text.
- After API compilation, new Readbacks could retain old data; native F7 through the UI updated their bindings, followed by Ctrl+F11.
- Disable continuous controls with Ctrl+F12 before batch DSP reads; otherwise the capture register and USB/API may contend or become delayed.
- Capture register 2074 (0x081A) worked reliably: 3-byte read, format 5.19. Select a point by writing 2 bytes: `(program_counter << 2) | 2` for MAC_out. Take `program_counter` from a **fresh** `trap.dat` after the latest compilation.
- Register 2075 was tried for independent capture but caused delays/timeouts; `capture_node.py` returned to the tested 2074.
- Parameter addresses change on compilation and when block order changes. An old coefficient address is not a constant.
- Changing a new, not-yet-compiled block's parameters with realtime active may address unassigned/incorrect locations. First build and load the connected schematic in a safe state, then change parameters and check the current map. Check all commands before a loaded test.
