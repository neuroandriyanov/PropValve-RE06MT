# Инструкции ИИ-ассистенту

## Назначение и источники

Это проект выносной платы управления Parker RE06M*T на ADAU1701. Обрабатываются постоянные сигналы; привычные предположения об аудиотракте, AC-связи и удалении DC здесь неприменимы. Аналоговый контур TL494 регулирует ток; цифровой ПИД не реализован.

Текущий эксплуатационный статус подтверждён автором 31.10.2026: **плата уже работает на машине, испытания пройдены, нагрев платы не наблюдается**. Не повторяй старый вывод, что объединённая система ещё не испытана. Это сообщение о работающем экземпляре; численные температуры и режимы испытаний не указаны, их не придумывай.

В начале работы прочитай `README.md`, `docs/STATUS.md`, `docs/SETUP.md`, `схема_плата/README.md`, затем материалы, относящиеся к задаче. Все пути ниже относительны корню репозитория. Не используй абсолютные пути, имя пользователя, HWND, PID и координаты из старой сессии.

Рабочий проект: `проект_сигма/Design1_parker_v0.dspproj`. Снимок: `Design1_parker_transfer_2026-10-27.dspproj`. При подготовке пакета они совпадали по SHA256:
`68473e7fcdd412021ea5be6c9a44e739b82610bf1e1b24db6d04dc68e22826e7`.
`*_io_calibrated`, `*_current_calibrated`, `*before*` и `*preliminary*` относятся к более ранним этапам.

Схема: `схема_плата/схема.pdf`. В актуальном PDF R42/R43 уже 10 кОм, в XLSX и на фото остаются старые 180 Ом. У DA7.2 есть авторская пометка «ошибка», возле DA7 на фото есть проводная доработка. Это замечания к воспроизведению по материалам, а не утверждение о неисправности работающей платы. Файлы `.dip`, `.dch`, библиотеки DipTrace и ZIP-дубликат Gerber автор исключил из пакета. Не восстанавливай их из соседней исходной папки без задачи. В комплекте есть PDF, распакованный Gerber и XLSX. Фото корпуса — `корпус/RUICHI A09.jpg`.

Историческое описание в `archive/НАЧАТЬ_ЗДЕСЬ_ПЕРЕНОС_ПРОЕКТА.txt` полезно для контекста. Его старые пути, состав CAD-файлов, утверждение о возможных 180 Ом в PDF и статус ещё не проведённых испытаний уточнены новыми документами и сообщением автора. Разрешения на оборудование из прошлых сессий не переносятся на другой стенд.

## Начальная проверка без оборудования

```powershell
py -3 tools/check_project.py
py -3 tools/sigma/inspect_project.py
py -3 -m unittest discover -s tools/meter -p "test_*.py" -v
```

Команды не обращаются к USB или SigmaStudio. Для них достаточно стандартной библиотеки Python 3.11+. Если `py` отсутствует, используй подходящий `python`/`python3` и проверь версию. `check_project.py` сравнивает пакет с манифестом поставки и таблицы с сохранённым проектом; это не аппаратный тест.

Для `.dspproj` применяй data-only парсер `tools/sigma/nrbf_project.py`. Он поддерживает найденный в этом проекте поднабор NRBF. Не загружай файл через .NET BinaryFormatter для анализа. Неподдерживаемую запись исследуй явно; не обходи ошибку десериализацией исполняемых объектов.

## Инварианты сохранённого проекта

- SigmaStudio 4.7, Fs = 96 кГц; DSP называется `IC 1`, EEPROM — `IC 2`.
- X4 / ADC0: 0–10 В → `VIN_LPF_20Hz` → `VIN_TABLE_0_10V` → `VIN_LIMIT_MIN/MAX` → команда 0–1.
- Команда → `CURRENT_0_3A` → `ZERO_OFF` → DAC0; через включённый `Inv1` → DAC1.
- `ZERO_CONSTANT=0`. Ненулевой первый коэффициент таблицы компенсирует аналоговое смещение. Ноль отключается отдельным `ZERO_OFF`.
- ADC1 → `CURRENT_LPF_20Hz` → `FB_LIMIT_MIN/MAX` (−0.78 / +0.70) → `I_FEEDBACK_0_1` → `Interpolator1` → DAC3 → X3.
- `DC2_3=0` задаёт DAC2. Отрицательные коэффициенты `Interpolator1` правильны для полярности выходного каскада.
- `VIN_MEAS_0_1 × 10` = входные вольты; `I_MEAS_0_1 × 3` = фактические амперы. X3 показывает фактический ток, а не копию задания.
- Ручные источники `CURRENT_INPUT_0_1` и `DC2_4` удалены из рабочей версии. Старые сценарии, обращающиеся к ним, неприменимы без адаптации.
- R42 = R43 = 10 кОм для текущих таблиц. Коэффициенты индивидуальны для измеренной платы.

## Работа на стенде

Сначала установи фактическое исполнение клапана, допустимый ток катушки, подключение и состояние питания. Шкала 3 А — результат прежнего стенда, не универсальный предел клапанов серии. Перед нагрузочным прогоном проверь отсутствие калибровочной перемычки X3–X4: в окончательной схеме она создаёт положительную обратную связь.

Выполняй уже согласованную пользователем работу без повторных вопросов. Если задача ограничена анализом файлов, не включай нагрузку, не загружай DSP и не записывай EEPROM. Недостающие сведения о подключённой нагрузке выясни до действий, меняющих её ток. Не считай ограничители DSP аппаратной защитой от сверхтока.

Файл на диске, RAM DSP и EEPROM — три разных состояния. В журнале калибровки от 27.10.2026 отмечено, что тогда EEPROM не записывалась. Позднее автор подтвердил работу платы на машине, но отдельные сведения о текущем содержимом EEPROM не передавал. Не переноси старую запись о EEPROM на текущую эксплуатацию как установленный факт. Для другого экземпляра проверяй загружаемый код; `archive/eeprom-unverified/` не является готовой проверенной прошивкой.

Перед использованием API собери мост по `docs/SETUP.md`. Путь к установленной среде задаётся `SIGMASTUDIO_DIR`; EXE собирается локально в `tools/bin/`. API способен изменять схему и аппаратные параметры: сначала проверь метод и аргументы. Вызов `capture_node.sample_node` тоже делает запись — выбирает точку регистра захвата, хотя не меняет задание тока.

После изменения схемы заново компилируй и проверяй соответствие загруженному проекту. `trap.dat` и `spi_map.dat` нужны от этой компиляции: адреса и program counter непостоянны. Сохранённые карты — исторический материал, не доказательство текущих адресов. Перед пакетным захватом выключи GUI continuous readback (Ctrl+F12); восстановление индикаторов — Ctrl+F11. Проверенный путь обновления привязки — штатный F7 в SigmaStudio при подготовленном стенде.

Readback: 3 байта, signed 5.19, делитель 524288. Управляющие параметры обычно 5.23; не путай форматы. Для захвата использовался 2074 (0x081A); 2075 давал тайм-ауты.

Мультиметр: UNI-T UT61D+, испытанный транспорт CH9329 `1A86:E429`. CP2110 реализован, но на исходном стенде не проверен. Для калибровки получай свежее измерение с `ok`, `checksum_valid`, `calibration_usable`; проверяй `quantity`, режим, единицы и `received_unix` (ориентир — не старше 3 с). Старый JSON не является живым показанием. Для режима тока нужен последовательный токовый вход, для напряжения — параллельный V/COM.

## Изменения и отчётность

Не запускай `archive/legacy-tools/` пакетом и не импортируй его модули: многие исполняют действия сразу при импорте. Там сохранены одноразовые сценарии с устаревшими окнами, именами блоков и заданиями до 3 А/10 В. Сначала прочитай и адаптируй нужный фрагмент под текущую задачу.

Сохраняй исходные снимки и исторические измерения. Новые логи помещай в игнорируемый `output/`, промежуточные файлы — в `tmp/`. Для нового подтверждённого результата создай отдельный датированный каталог в `measurements/` и опиши конфигурацию. Не перезаписывай исходные протоколы результатами расчёта.

После правок Python выполняй соответствующие проверки без оборудования. Изменения `.dspproj` дополнительно сверяй по таблицам, константам, соединениям и свежему netlist. Проверка парсера не заменяет проверку компиляции и испытание. Указывай, что именно проверено: файл, компиляция, RAM, EEPROM, ток или гидравлика.

`docs/manifest.json` — контрольные суммы текущей подготовленной версии пакета. История состава отражена в `docs/INVENTORY.md`. При разработке расхождение ожидаемо; не обновляй их автоматически, чтобы скрыть изменение. Сначала проверь diff и задокументируй новую версию. Не публикуй репозиторий и не отправляй материалы наружу без задачи пользователя.
