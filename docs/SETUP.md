# Запуск на другом компьютере

## Просмотр и проверка без платы

Скопируйте папку целиком и откройте терминал в её корне. Для проверки файлов нужны Python 3.11+ и стандартная библиотека; дополнительных pip-пакетов нет.

Авторская плата уже работает на машине и прошла испытания без наблюдаемого нагрева. Ниже описана подготовка другого компьютера и подключение другого экземпляра, а не незавершённый запуск авторской машины.

```powershell
py -3 --version
py -3 tools/check_project.py
py -3 tools/sigma/inspect_project.py
py -3 -m unittest discover -s tools/meter -p "test_*.py" -v
```

`inspect_project.py` выводит JSON с именами блоков, таблицами и константами. Можно указать другую копию:

```powershell
py -3 tools/sigma/inspect_project.py "проект_сигма/Design1_parker_transfer_2026-10-27.dspproj"
```

Сами скрипты находят корень по своему расположению. Приведённые относительные команды выполняются из корня пакета. На Linux/macOS офлайн-команды запускаются через `python3`.

## Среда для подключения

| Компонент | Для чего нужен |
| --- | --- |
| Windows | SigmaStudio и прямой USB/HID-доступ из утилиты мультиметра |
| Analog Devices SigmaStudio 4.7 | Версия, использованная в исходной работе; другие версии здесь не испытаны |
| USBi / совместимый программатор и его драйвер | Подключение к ADAU1701; конкретную модель и распиновку проверить по своему оборудованию |
| Python 3.11+, предпочтительно x64 | Проверки, чтение прибора, клиент API |
| .NET Framework 4.x с `csc.exe` | Необязательно: локальная сборка моста штатного API SigmaStudio |
| PDF-просмотрщик / Gerber-просмотрщик | Просмотр схемы и производственных файлов платы |

Программы и драйверы устанавливаются отдельно из источников их производителей. Этот пакет не включает установщики, коммерческие DLL и программу UNI-T. Для собственного HID-опроса DLL программы UNI-T не нужны.

Исходники DipTrace и библиотеки исключены автором; для работы с текущим комплектом DipTrace не требуется.

## Открытие проекта

Откройте `проект_сигма/Design1_parker_v0.dspproj` в SigmaStudio. Сохраните имя: от него зависят имена каталогов компилятора. Если путь содержит кириллицу и конкретная установка с ним не работает, перенесите рабочую копию в совместимый путь и согласованно измените пути инструментов.

Проверьте `IC 1`, частоту 96 кГц, аппаратные подключения и индикаторы `ADC0_RAW`, `VIN_FILTERED`, `VIN_MEAS_0_1`, `ADC1_RAW`, `I_MEAS_0_1`. До загрузки проверьте текущую схему и [ограничения](STATUS.md).

На подготовленном стенде штатная команда **Action → Link Compile Download (F7)** компилирует проект и загружает RAM DSP. Это действие может изменить ток катушки. Оно выполняется после проверки нагрузки, нулевого задания и отсутствия перемычки X3–X4. При выключении питания содержимое RAM теряется; наличие файлов EEPROM не доказывает, что в EEPROM записана эта версия.

Непрерывное чтение индикаторов: Ctrl+F11 — включить, Ctrl+F12 — выключить. Перед пакетным чтением через API непрерывные индикаторы отключают, чтобы они не конкурировали за регистр захвата.

## Мультиметр

Проверенный прибор — UNI-T UT61D+ с HID-адаптером CH9329. Из корня пакета:

```powershell
.\tools\meter\meter.ps1 --list
.\tools\meter\meter.ps1 --count 1
.\tools\meter\meter.ps1 --count 0 --interval 1 --latest output/meter/latest.json --log output/meter/readings.jsonl
```

Последняя команда работает до Ctrl+C. Launcher выбирает `PROPVALVE_PYTHON`, затем `py -3`, затем `python`. При необходимости задайте свой исполняемый файл:

```powershell
$env:PROPVALVE_PYTHON = 'D:\Python311\python.exe'
```

Вместо PowerShell-скрипта можно вызвать `py -3 tools/meter/read_meter.py` с теми же аргументами. Если найдено несколько адаптеров, выберите `--path` из свежего `--list`. Утилита не переключает режим измерения: DC V / DC A и подключение щупов задаются на приборе. Для `CP2110` она также устанавливает временные параметры UART; этот транспорт не был проверен на исходном стенде.

Проверяйте свежесть, единицы и флаги JSON. При `HOLD`, `REL`, `MIN/MAX`, `PEAK`, перегрузке или низкой батарее измерение не используют для калибровки. Если штатное приложение мешает опросу, остановите его опрос. [Описание протокола](../tools/meter/ИНСТРУКЦИЯ.txt).

## Необязательная автоматизация SigmaStudio

Мост собирается из исходника; готового EXE в пакете нет. Он использует DLL установленного SigmaStudio. При стандартной установке 4.7 путь определяется автоматически; для другого каталога задайте переменную **в том же терминале, из которого будете использовать мост**:

```powershell
$env:SIGMASTUDIO_DIR = 'C:\Program Files\Analog Devices\SigmaStudio 4.7'
.\tools\sigma\build_bridge.ps1
.\tools\bin\SigmaBridge2.exe inspect
```

`inspect` выводит доступные типы и методы без создания объекта сервера. Это проверка доступности DLL, а не связи с DSP. Для работы через `call` требуется запущенная SigmaStudio с нужным проектом и доступным штатным сервером автоматизации. Список методов следует брать из установленной версии: в некоторых именах API встречается `SAFELAOD`.

`tools/sigma/sigma_api.py` использует локальный `tools/bin/SigmaBridge2.exe`. При необходимости другой EXE задаётся через `PROPVALVE_SIGMA_BRIDGE`. Каталог результатов компиляции можно задать через `PROPVALVE_COMPILED_DIR` (папка, в которой непосредственно лежит `trap.dat`). По умолчанию это `проект_сигма/IC 1_Design1_parker_v0/net_list_out2`.

Перед чтением конкретной точки получите свежий `trap.dat` из проекта, действительно загруженного в DSP. `capture_node.sample_node` выбирает точку регистра захвата записью 2074, затем читает значения. Этот помощник не проверяет соответствие RAM и карты самостоятельно.

Вызов `call` — универсальный API, включая изменение параметров, схемы и загрузку DSP. Готовой команды автоматического прогона катушки в стартовой инструкции нет: старые сценарии требуют адаптации к конкретному стенду и текущему проекту.
